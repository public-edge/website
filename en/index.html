Route public traffic by health, not hope.

Kubernetes can expose workloads, but it does not decide which regional edge is reachable, has capacity and is healthy right now. Public Edge Manager turns that evidence into deterministic DNS answers and auditable PublicEdge status.

Boundaries

It chooses the edge. It does not run the network.

Public Edge Manager is application- and DNS-provider-agnostic. Optional integrations add evidence or publication; none of them is required.

Public Edge Manager does

  • Candidate discovery · from Nodes, Gateways and Services, not a private inventory
  • Exclusion on evidence · stale, unreachable or unready candidates never publish
  • Controlled failover · last-known-good through short probe failures
  • Authoritative DNS · delegated zone over UDP and TCP

It never configures

  • Routers, NAT and BGP · owned by their existing operators
  • Certificates and app routes · owned by their controllers
  • DNS provider credentials · ExternalDNS writes to PowerDNS; the credential stays there
  • Path evidence · read from AdvFab NetworkPathAssessment resources

Install

Nothing is published until the evidence is there.

The chart defaults to enabled: false. An edge is only published once the service directory, nameserver fallback and readiness evidence are configured.

  1. Copy the example values and replace every documentation address and domain.
  2. Install the signed OCI chart.
  3. Register a service and inspect the derived status from the least-privilege CLI pod.
CLI guide →
install.sh
helm install public-edge-manager \
  oci://ghcr.io/public-edge/charts/public-edge-manager \
  --version 0.8.4 \
  --namespace public-edge-system --create-namespace \
  --values values-production.yaml

# Register a service, then inspect
kubectl -n public-edge-system exec deploy/public-edge-manager-cli -- \
  edgectl service-register app.example.com \
  --service app --class web --probe-path /healthz
kubectl -n public-edge-system exec deploy/public-edge-manager-cli -- \
  edgectl status
